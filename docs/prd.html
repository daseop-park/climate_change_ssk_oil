제품 개요

배달음식 용기의 기름때를 닦아내는 기름 흡수 패드 위에 6자리 코드(형식 ABC-123)가 인쇄되어 있다. 참가자는 QR을 스캔해 사이트에 진입하고, 이름·전화번호·코드를 입력하면 즉시 당첨 경품을 확인한다. "꽝"은 존재하지 않는다 — 모든 코드는 발급 시점에 이미 특정 상품에 배정되어 있으며, 참가상부터 5만원 상당 기프트카드까지 등급만 다르다. 참가자는 이후 /mypage에서 이름+전화로 자신의 당첨 내역을 다시 조회할 수 있고, 실물 수령은 현장 운영자가 관리자 콘솔에서 RECEIVED로 처리한다.

배경

기후 행동 공모전 출품작으로 개발된 실사용 캠페인 앱으로, 팀명이자 서비스명이 "싹싹기름"이다. QR 전용 도메인이며 robots.ts가 전체 색인을 차단해 검색엔진에 노출되지 않도록 설계되어 있다 — 오프라인 이벤트 현장 유입만을 전제한 제품이다.

목표 · 성공 지표

추정 명시적 KPI 문서는 없으나, 코드의 설계 결정으로부터 다음 목표를 역산할 수 있다.

  • 참여 마찰 최소화 — 로그인 없이 이름+전화만으로 참여·조회 가능. 세션은 새로고침 시 소멸(개인정보 최소 보관 원칙).
  • 재고·확률의 정확성 — 당첨 재고를 별도 컬럼으로 저장하지 않고 reward_codes 상태를 항상 카운트해서 파생시킨다. 과거 표시 확률이 실제와 어긋난 버그(86% vs 실제 100%)를 계기로 "저장하지 말고 항상 계산하라"는 원칙이 굳어졌다.
  • 동시성 안전성 — 동일 코드에 대한 동시 등록 요청이 정확히 1건만 성공해야 한다. Phase 6.5에서 2개 프로세스 × 8동시 요청으로 실제 검증됨.
  • 개인정보 보호 — 전화번호는 저장 시점부터 암호화·해시화되며, 관리자 화면에서도 기본은 마스킹, 평문 열람은 별도 API로 분리.
  • 운영 부담 최소화 — 관리자 콘솔은 "읽기 전용 단일 화면"이 원칙. 상품 등록·배치 발급·CSV 추출은 의도적으로 UI화하지 않고 CLI로 남겨 개발 범위를 축소했다 (docs/phase5-admin-estimate.md).

비기능 요구사항

  • 보안 — 전화번호 AES-256-GCM 암호화 + HMAC-SHA256 조회용 해시, 관리자 비밀번호 scrypt, 모든 비교는 timingSafeEqual. 대칭키(PHONE_ENCRYPTION_KEY/PHONE_HMAC_SECRET)는 런칭 후 절대 교체 불가(기존 데이터 복호화 불능).
  • 동시성 — 상태 전이(UNUSED→USED→RECEIVED)는 읽고-쓰지 않고 조건부 updateMany + 영향 행 수로 성공을 판정. 멀티 프로세스 부하 테스트로 검증됨.
  • 접근성 — 포커스 트랩, inert, ARIA 속성 적용(Phase 6 감사에서 보강).
  • 레이트리밋 — 인메모리 슬라이딩 윈도우, 실패 요청만 카운트. 알려진 한계 동시 요청 하에서 우회 가능성 있음 → 상세는 12장.
  • 배포 제약 — 단일 인스턴스 전제(레이트리밋·사이트게이트 카운터가 프로세스 메모리에 상주). 수평 확장 시 재설계 필요.
  • 비색인 — robots.ts로 전체 차단, QR 진입만 전제.

데이터 모델

PostgreSQL · Prisma 7 (@prisma/adapter-pg). 관계: User (1) — N — RewardCode — 1 — Product.

계층 구조

모든 쓰기 경로가 동일한 5단 계층을 통과한다. Repository는 판단하지 않고 Prisma만 호출하며, 비즈니스 규칙은 오직 Service에만 존재한다 (유일한 예외: 상품 소프트 삭제는 CLI 경로 특성상 Repository에 가드를 둠).

↓

parseBody / parseQuery
↓

비즈니스 규칙 + 트랜잭션 경계

CLI 스크립트(scripts/*.ts)도 Service를 직접 호출한다 — CLI와 향후 관리 UI가 동일한 비즈니스 로직을 공유하도록 한 의도적 설계.

이중 인증 게이트 — src/proxy.ts

Next 16의 middleware.ts는 Edge 런타임 전용이라 jsonwebtoken/node:crypto를 실행할 수 없다. 이 프로젝트는 대신 Node 런타임에서 도는 proxy.ts를 관례상 진입점으로 사용한다 — 과거 학습 데이터 기준으로 middleware.ts를 기대하면 빌드가 조용히 깨지는 지점이다.

Site Gate

?k=TOKEN을 timingSafeEqual로 비교 → 통과 시 토큰의 SHA-256 해시를 7일 쿠키로 저장, ?k=는 307로 제거.

기본 비활성(fail-open) — 포트폴리오 열람자가 락아웃되지 않도록. 명시적으로 켜면 fail-closed.

Admin Auth

관리자 테이블 없이 ADMIN_PASSWORD_HASH 환경변수 1개(scrypt:salt:hash)로 검증. httpOnly·SameSite=Strict JWT, 8h TTL.

(console)/layout.tsx가 동일 쿠키를 한 번 더 검사 — 프록시 매처 오설정에 대한 심층 방어.

도메인 규칙: 사전배정 추첨

당첨 확률은 등록 시점이 아니라 발급 시점(db:issue)에 확정된다. 등록은 이미 정해진 배정을 "청구(claim)"하는 순수 트랜잭션일 뿐이다 — 실시간 추첨 로직이 존재하지 않는다는 점이 이 시스템을 다른 응모/추첨 서비스와 구분 짓는 핵심 설계.
