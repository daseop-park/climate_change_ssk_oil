## 1. 문제 정의

`src/` 전체에 **Tailwind 브레이크포인트(`sm:` `md:` `lg:` `xl:` `2xl:`)가 0건**입니다.
`globals.css` 의 미디어쿼리도 `prefers-reduced-motion` 하나뿐이고 폭 관련은 없습니다 (`globals.css:243`).
반응형이 부족한 것이 아니라 **아예 없는** 상태입니다.

증상은 두 영역에서 정반대로 나타납니다.

| 영역 | 현재 코드 | 증상 |
|---|---|---|
| 사용자 앱 | `AppShell.tsx:20` — `w-full max-w-[440px] h-[100dvh]` | 데스크톱에서 화면 한가운데 **440px 스트립**, 나머지는 `--color-page-bg`(#E4EBE5) 단색 |
| 관리자 콘솔 | `(console)/layout.tsx:36` — `min-w-[1120px]` | 1120px 미만에서 **가로 스크롤**. 폰·태블릿 사용 불가 |

세로 방향은 이미 정상입니다 — 사용자 페이지 5개 모두 `overflow-y-auto` 스크롤 컨테이너를
가지고 있어 짧은 화면에서도 내용이 잘리지 않습니다.
**이 작업의 범위는 순수하게 가로입니다.**

### ⚠️ 이건 버그가 아니라 의도된 결정이었습니다

440px 셸은 QR 전용 모바일 캠페인이라는 성격에서, 1120px 는 `phase5-admin-estimate.md` §8
에서 나온 판단입니다. 따라서 이 문서의 과제는 "고치기"가 아니라 **"의도를 유지한 채 어디까지
범위를 넓힐 것인가"** 이고, 아래 비목표가 목표만큼 중요합니다.

## 2. 목표 · 비목표

**목표**

1. 데스크톱에서 사용자 앱이 미완성으로 보이지 않을 것
2. 현장 운영자가 **폰으로 수령 처리**를 할 수 있을 것 (`/admin/wins`)
3. 브레이크포인트 체계를 한 번 정해서 이후 작업이 그 위에 쌓이게 할 것

**비목표 (명시적으로 하지 않는 것)**

1. **모바일 화면의 어떤 변화도 만들지 않는다.** 브레이크포인트 미만에서는 DOM·스타일이
   현재와 100% 동일해야 합니다. 이것이 이 작업의 가장 강한 제약입니다.
2. 사용자 앱을 데스크톱 전용 레이아웃(2단 구성 등)으로 재설계하지 않는다 — 디자인 핸드오프와
   정면 충돌하고, QR 전용이라는 서비스 성격에도 맞지 않습니다.
3. 관리자 콘솔 **전체**를 반응형으로 만들지 않는다 (§5 티어 구분 참조).
4. 기존 고정 px 값(`h-[38px]`, `w-[344px]` 등 20여 곳)을 상대 단위로 일괄 치환하지 않는다.
   디자인 스펙의 수치이고, 셸 폭이 고정인 한 문제를 일으키지 않습니다.

## 3. 브레이크포인트 체계

**Tailwind v4 기본값을 그대로 쓰고 커스텀 브레이크포인트를 추가하지 않습니다.**
`globals.css` 의 `@theme` 에 `--breakpoint-*` 가 없으므로 현재 기본값이 적용됩니다.

| 토큰 | 폭 | 이 프로젝트에서의 의미 |
|---|---|---|
| `md:` | 768px | 태블릿 — 관리자 콘솔이 세로 스크롤만으로 동작하기 시작하는 지점 |
| `lg:` | 1024px | 데스크톱 — 사용자 앱 배경 연출, 관리자 사이드바 고정 |

`sm:` `xl:` `2xl:` 는 이번 범위에서 쓰지 않습니다. 쓸 곳이 생기면 이 표에 먼저 추가하고
의미를 정의한 뒤 사용합니다 — 근거 없이 늘어난 브레이크포인트가 반응형을 못 쓰게 만드는
가장 흔한 경로입니다.

**규칙: 모바일 퍼스트.** 기본 클래스는 항상 모바일이고, `md:`/`lg:` 는 **덧붙이기만** 합니다.
`max-lg:` 같은 역방향 변형은 쓰지 않습니다 — 비목표 1(모바일 무변화)을 코드 차원에서
보장하기 위해서입니다. 역방향을 쓰는 순간 모바일 스타일이 조건부가 되고, 리뷰에서
"모바일이 안 바뀌었는가"를 눈으로 검증할 수 없게 됩니다.

## 4. Part A — 사용자 앱 데스크톱 (셸 유지 + 배경 연출)

### 4-1. 접근

440px 셸을 **그대로 두고**, `lg:` 이상에서 그 바깥 여백을 캠페인 비주얼로 채웁니다.
셸 내부(페이지 5개, Intro, Drawer, PrizeSheet, RevealModal)는 **한 줄도 건드리지 않습니다.**

```
┌──────────────── lg: 이상 ────────────────┐
│  ░░░ 풀뷰포트 배경 (어둡게 처리) ░░░       │
│                                          │
│   기름 한 방울부터    ┌────────────┐      │
│   지구는 달라집니다.  │  440px 셸  │      │
│                      │  현재 그대로│      │
│   □ 아미유            │            │      │
│   □ 사랑의열매        └────────────┘      │
│                                          │
└──────────────────────────────────────────┘

lg: 미만 → 현재와 완전히 동일 (배경 레이어 자체가 렌더되지 않음)
```

### 4-2. 구조

`AppShell.tsx:19` 의 바깥 래퍼가 유일한 수정 지점입니다.

```
현재:  <div className="bg-page-bg flex min-h-[100dvh] items-start justify-center">
         <div className="... max-w-[440px] h-[100dvh] ...">   ← 셸
         
설계:  <div className="bg-page-bg relative flex min-h-[100dvh] items-start justify-center
                       lg:items-center">
         <DesktopBackdrop />        ← 신규, lg: 미만에서는 null 반환
         <div className="... max-w-[440px] h-[100dvh] z-10
                         lg:h-[min(880px,92dvh)] lg:rounded-[32px] ...">   ← 셸
```

**신규 컴포넌트 `src/components/shell/DesktopBackdrop.tsx`**

- `hidden lg:block` 이 아니라 **컴포넌트 레벨에서 `lg:` 유틸리티로만** 제어합니다.
  서버에서 뷰포트를 알 수 없으므로 JS 분기(`useMediaQuery` 등)를 쓰면 하이드레이션
  불일치와 깜빡임이 생깁니다. CSS 로만 숨깁니다.
- 배경 이미지는 `/assets/intro-bg-earth.png` 를 재사용합니다.
  `next/image` 의 `fill` + `sizes="100vw"` + 어둡게 처리(overlay)로 셸이 떠 보이게 합니다.
  **`priority` 는 붙이지 않습니다.** 설계 때는 "Intro 가 이미 `priority` 로 받으니 추가
  비용이 없다"고 적었지만, `sizes` 가 달라(`440px` vs `100vw`) srcSet 후보가 갈라지므로
  실제로는 **다른 파일을 한 장 더 받습니다.** 기본 `loading="lazy"` 로 두면 `display:none`
  인 동안(=`lg:` 미만) 레이아웃 박스가 없어 뷰포트와 교차하지 않고, 브라우저가 아예
  요청하지 않습니다 — 모바일에 한 바이트도 늘지 않습니다. (`display:none` 인 `<img>` 라도
  `eager` 면 그냥 받아 갑니다. 이 한 속성이 비목표 1 을 지키는 지점입니다.)
- 좌측 카피는 `Intro.tsx:84` 의 문구("기름 한 방울부터 / 지구는 달라집니다")와 로고 2종을
  재사용합니다. **새 카피를 만들지 않습니다** — 디자인 스펙에 없는 문구를 즉흥으로 넣으면
  나중에 스펙과 어긋납니다.
- 순수 장식이므로 `aria-hidden` 을 답니다. 같은 정보가 이미 셸 안 `Intro` 에 접근 가능한
  형태로 존재하므로, 스크린리더에 두 번 읽히는 것이 오히려 손해입니다.

### 4-3. 셸 프레임 처리

`lg:` 에서 셸에 `rounded-[32px]` 와 높이 제한(`min(880px,92dvh)`)을 주어 "화면에 놓인 앱"처럼
보이게 합니다. 검토된 부작용:

- `overflow-hidden` 이 이미 있어 둥근 모서리로 내부가 삐져나오지 않습니다 (`AppShell.tsx:20`)
- `Intro` 는 `absolute inset-0` 이라 셸 높이가 줄어도 그대로 따라옵니다 (`Intro.tsx:15`)
- 내부 페이지는 `flex-1 overflow-y-auto` 라 셸이 짧아지면 스크롤 영역이 짧아질 뿐입니다
- `Drawer`(`w-4/5 max-w-[320px]`)·`PrizeSheet`(`max-h-[88%]`)는 모두 셸 기준 상대값이라
  함께 줄어듭니다

⚠️ **`h-[100dvh]` → `lg:h-[min(880px,92dvh)]` 는 셸 안 모든 절대 위치 요소에 영향을 줍니다.**
구현 시 `RevealModal` 의 당첨 연출과 `Drawer` 열림 상태를 데스크톱 폭에서 반드시 눈으로
확인하세요. 계산으로는 안전하지만 애니메이션 끝점은 실측이 필요합니다.

### 4-4. 함께 처리할 것

`src/app/not-found.tsx:23` 이 동일한 `max-w-[440px]` 셸을 독립적으로 그리고 있습니다.
같은 처리를 하지 않으면 404 만 데스크톱에서 옛 모습으로 남습니다. 404 는 배경 연출까지는
필요 없고, 최소한 셸 프레임(`lg:rounded` / 높이)만 맞춥니다.

### 4-5. 영향 파일

| 파일 | 변경 |
|---|---|
| `src/components/shell/DesktopBackdrop.tsx` | **신규** |
| `src/components/shell/AppShell.tsx` | 래퍼 클래스 + 컴포넌트 삽입 (약 4줄) |

## 5. Part B — 관리자 콘솔 모바일

### 5-1. 티어 구분

관리자 콘솔 4개 화면을 전부 반응형으로 만들지 않습니다. **현장에서 실제로 쓰는 화면만** 합니다.

| 티어 | 화면 | 근거 |
|---|---|---|
| **T1 — 필수** | `/admin/login`, `/admin/wins` | 행사장에서 폰·태블릿으로 수령 처리. 유일한 쓰기 화면이자 유일한 현장 업무 |
| **T2 — 최소 대응** | `/admin`, `/admin/codes`, `/admin/prizes` | 조회 전용이고 데스크톱에서 봅니다. 가로 스크롤을 **페이지 단위로 옮기는** 것까지만 |

T2 를 "최소 대응"으로 두는 이유: 현재 `min-w-[1120px]` 이 **레이아웃 최상단**에 있어서
좁은 화면에서 사이드바까지 함께 밀립니다. 이걸 각 화면의 테이블·차트 컨테이너로 내리면,
폰에서도 사이드바와 헤더는 정상이고 **넓은 표만** 가로 스크롤됩니다. 레이아웃을 재설계하지
않고 얻는 가장 큰 개선입니다.

### 5-2. 사이드바

`AdminSidebar.tsx:21` 이 `w-[224px]` 고정입니다.

- `lg:` 이상 — 현재 그대로 고정 사이드바
- `lg:` 미만 — 상단 바(로고 + 메뉴 버튼) + 슬라이드 드로어

⚠️ **사용자 셸의 `Drawer.tsx` 를 재사용할 수 없습니다.** 그쪽은 `ShellContext` 에 묶여 있고
(`ShellContext.tsx` 를 9곳이 참조), 그 컨텍스트는 `(app)` 레이아웃에서만 제공됩니다.
관리자용은 별도의 가벼운 드로어를 만들어야 합니다. 열림 상태는 `AdminSidebar` 내부
`useState` 로 충분합니다 — 다른 컴포넌트가 알 필요가 없습니다.

포커스 트랩·`inert`·`Esc` 닫기는 `hooks/useDialog.ts` 를 재사용합니다. 이미
`Drawer`·`PrizeSheet`·`RevealModal` 3곳이 쓰는 검증된 훅이라 접근성 처리를 새로 짤 이유가
없습니다.

### 5-3. 당첨 내역 화면 (`/admin/wins`)

현장 업무의 핵심 화면입니다. 두 부분으로 나뉩니다.

**① 수령 처리 패널 (`AdminReceivePanel.tsx`)** — 이름+전화 조회 → 체크박스 선택 → 일괄 처리.
폼이라 세로 스택으로 자연스럽게 접힙니다. `components/form/FieldSet.tsx` 를 쓰고 있어
필드 자체는 이미 `w-full` 기반입니다. 버튼 열만 `flex-col md:flex-row` 처리하면 됩니다.

**② 당첨 목록 테이블 (`AdminTable.tsx`)** — 여기가 실제 작업량입니다.
`AdminTable` 은 `/admin/codes`, `/admin/prizes`, `/admin/wins`, `AdminRecentWinsTable`
**4곳이 공유**하는 컴포넌트입니다. 모바일 카드 전환을 컴포넌트 안에 직접 넣으면 T2 화면까지
영향을 받습니다.

→ **설계 결정: `AdminTable` 은 건드리지 않고, `/admin/wins` 페이지에서 `lg:` 미만일 때
렌더할 카드 리스트를 별도 컴포넌트로 만듭니다.**

```
<div className="hidden lg:block"><AdminTable … /></div>
<div className="lg:hidden"><AdminWinCards … /></div>
```

같은 데이터를 두 번 렌더하는 비용이 있지만, 공유 컴포넌트에 화면별 분기를 심는 것보다
훨씬 안전합니다. 행 수는 페이지네이션으로 제한돼 있어 실제 비용은 무시할 수준입니다.

`min-w` 값은 컬럼 수에서 나왔습니다 — 당첨 내역 8컬럼 880px, 발급 이력 6컬럼 620px,

이 하한은 `lg:` 이상에서도 필요합니다 — 1024px 에서 사이드바 224px 를 빼면 본문이 800px 이라
예전 하한이 보장하던 폭(1120 − 224 = 896px)보다 좁습니다.

## 6. 검증 계획

**뷰포트 매트릭스** — 360 / 390 / 744 / 1024 / 1440 / 1920

| 폭 | 사용자 앱 기대 | 관리자 기대 |
|---|---|---|
| 360·390 | **현재와 픽셀 단위로 동일** | 상단 바 + 드로어, 수령 처리 가능 |
| 744 | 현재와 동일 | 상단 바 + 드로어, 표는 카드 |
| 1024 | 배경 연출 등장, 셸 프레임 | 고정 사이드바, 표 |
| 1440·1920 | 배경 연출 | 현재와 동일 |

**모바일 무변화 회귀 (비목표 1 검증)** — 가장 중요합니다.
`lg:` 미만에서 변경 전후 스크린샷을 비교합니다. 차이가 있으면 설계 위반입니다.
`max-lg:` 를 쓰지 않기로 한 것이 이 검증을 가능하게 만듭니다.

**기능 회귀**
- 인트로 진입 애니메이션 → 코드 입력 → 당첨 연출(`RevealModal`) 전체 흐름을 1440px 에서
- Drawer·PrizeSheet 열림/닫힘을 1440px 에서 (4-3 의 높이 변경 영향)
- `/admin/wins` 조회 → 선택 → 수령 처리를 390px 에서
- 키보드 전용으로 관리자 드로어 열고 닫기 (`useDialog` 동작 확인)

**빌드**
- `npm run typecheck` · `npm run lint` · `npm run build`
- `npm run test:api` 는 이 작업과 무관하지만(서버 라우트 무변경) 한 번 돌려 확인

## 9. 구현하며 달라진 것

설계에 없었거나 설계와 다르게 간 것만 적습니다. 나머지는 §4·§5 그대로입니다.

### 9-1. `DesktopBackdrop` 은 `priority` 를 붙이지 않습니다

§4-2 에 반영했습니다. 요약하면 — 설계가 전제한 "이미 받은 이미지라 공짜"가 사실이 아니었고,
대신 기본 `lazy` 가 `display:none` 과 맞물려 **모바일에서 요청 자체를 없애** 목적을 더 정확히
달성합니다.

### 9-2. 상태 라벨·색 표를 한 곳으로 모았습니다

`/admin/wins` 페이지와 `AdminRecentWinsTable` 이 `STATUS_LABEL`·`STATUS_CLASS` 를 **각자 한 벌씩**
가지고 있었습니다. 카드까지 만들면 세 벌이 됩니다. 그래서 `AdminWinCards.tsx` 가
`WIN_STATUS_LABEL`·`WIN_STATUS_CLASS` 를 export 하고 `/admin/wins` 가 가져다 씁니다 — 한 화면 안의
표와 카드가 다른 말을 하는 것이 가장 나쁜 결과라서, 적어도 그 둘은 같은 표를 봐야 합니다.
(`AdminRecentWinsTable` 은 다른 화면이라 건드리지 않았습니다. 두 벌로 줄었습니다.)

### 9-3. 드로어에 두 가지를 더 넣었습니다

설계는 "`useState` + `useDialog` 면 끝"이라고 봤는데, 둘 다 **드로어가 CSS 로만 숨겨지기 때문에**
생기는 문제입니다.

1. **`lg:` 로 넓어질 때 닫기** — 드로어가 열린 채 창을 넓히면 `lg:hidden` 으로 사라지지만
   `open` 은 `true` 로 남습니다. `useDialog` 의 포커스 트랩만 살아서 **Tab 이 갇힙니다**.
   `matchMedia("(min-width: 64rem)")` 로 닫습니다.
2. **경로가 바뀌면 닫기** — 링크의 `onClick` 만으로는 뒤로 가기를 못 잡습니다.
   `useEffect` 가 아니라 **렌더 중 조정**(이전 경로를 state 로 들고 비교)입니다. effect 로 하면
   열린 화면이 한 번 그려진 뒤 닫혀 깜빡이고, `react-hooks/set-state-in-effect` 가 막습니다.

사이드바 내부는 `Brand`·`NavList`·`Account` 셋으로 쪼갰습니다. 고정 사이드바와 드로어가
같은 내용을 그려야 하는데, 마크업을 두 벌 두면 메뉴를 늘릴 때 한쪽만 고쳐집니다.

### 9-4. T2 에서 그리드도 세로로 쌓았습니다

설계(§5-1)는 "가로 스크롤을 페이지 단위로 내리는 것"까지였습니다. 그런데 대시보드의
`grid-cols-3`·`grid-cols-[1.55fr_1fr]` 은 **분수 그리드라 좁아져도 가로 스크롤이 나지 않습니다** —
대신 찌그러져서, 360px 에서 KPI 카드 한 장이 100px 이 되고 숫자가 줄바꿈됩니다.
가로 스크롤을 옮기는 것만으로는 이 화면이 개선되지 않아, `md:grid-cols-3` /
`lg:grid-cols-[1.55fr_1fr]` 한 클래스씩을 더 붙였습니다. 차트 내부는 손대지 않았습니다.

### 9-5. 남은 것 — §6 육안 검증

코드로 확인할 수 있는 데까지는 했습니다.

- `npm run typecheck` · `npm run lint` · `npm run build` 통과
- `npm run test:api` **63건 전체 통과** (서버 라우트 무변경 확인)
- 빌드 산출 CSS 에 `@media (min-width:48rem)` · `@media (min-width:64rem)` 두 블록만 존재.
  `sm:` `xl:` `2xl:` `max-*:` 는 0건 — §3 대로입니다
- 렌더된 HTML 로 확인: 사용자 셸의 `lg:` 클래스와 `DesktopBackdrop`(`loading="lazy"`),
  404 셸 프레임, 콘솔 4개 화면의 상단 바·드로어·고정 사이드바 공존,
  `min-w-[1120px]` 소멸, `/admin/wins` 의 표 10행과 카드 10장 동시 렌더

**하지 못한 것은 §6 의 뷰포트 매트릭스와 모바일 무변화 스크린샷 비교입니다.** 이 환경에
브라우저 자동화가 없습니다. 특히 다음 셋은 계산이 아니라 눈으로 봐야 합니다.

- 4-3 의 ⚠️ — 1440px 에서 인트로 진입 애니메이션 · `RevealModal` 당첨 연출 · `Drawer` 열림
  (셸 높이가 `100dvh` → `min(880px,92dvh)` 로 바뀐 영향)
- `lg:` 미만 스크린샷 전후 비교 (비목표 1)
- 390px 에서 `/admin/wins` 조회 → 선택 → 수령 처리 한 바퀴
