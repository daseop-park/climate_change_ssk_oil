## 1. 현재 상태 대조

### 화면 — 0%

`src/app/admin/` 이 없습니다. 로그인 페이지를 포함해 관리자 화면은 한 장도 없습니다.

> ✅ **2026-08-10 해소.** 5.1 에서 셸·로그인·자리표시 4화면을 만들었습니다. 아래 §4 참고.

### API — 조회 전용 기준 약 80%

| 화면 요구 | 현재 | 갭 |
|---|---|---|
| 로그인·로그아웃 | `POST /api/admin/login`·`logout` | 없음 |
| KPI 3종 | `GET /api/admin/dashboard` | 사용률·소진율 **파생 계산 필요** (분모용 발급 총량이 응답에 없음) |
| 일별 코드 사용 스택 막대 14일 | **없음** | `usedAt` 일자별 `groupBy` 신규 |
| 경품별 잔여 게이지 | `DashboardResponse.stock` | 그대로 씀 |
| 최근 당첨 테이블 | `recentReceived` | **성함 평문**, 배치 컬럼 없음 |
| 발급 이력 | `GET /api/admin/reward-code` | 배치명·수량만. 사용 수·발급일 없음 (`min(createdAt)` 으로 파생) |
| 경품 현황 | `/api/admin/product` GET + `dashboard.stock` | 없음 (POST·PATCH·DELETE 는 화면에서 안 씀) |
| 당첨 내역 목록 | **없음** | 신규 |
| 실물 지급 | `PATCH /api/reward/receive` | **인증 밖.** `/api/admin/` 아래로 이관 필요 |

### 인증 — 구멍 하나

> 📌 **2026-08-09 갱신.** [사이트 게이트 작업](./implementation-plan.md#사이트-게이트--전역-서킷-브레이커-2026-08-09)으로 `proxy.ts` 가 이미 바뀌었습니다. matcher 는 **정적 자원을 뺀 전 경로**를 덮고 있고, 게이트 분기와 `isApiPath()` 헬퍼도 이미 있습니다. 아래 설명과 §5 는 그 위에서 읽으세요.

**페이지 라우트 `/admin` 은 여전히 관리자 인증 대상이 아닙니다.** proxy 는 `/api/admin` 으로 시작하는 경로에만 토큰을 요구합니다. 5.1 에서 화면을 만드는 순간, (게이트가 꺼져 있으면) 인증 없이 열리는 관리자 페이지가 생깁니다.

남은 작업은 **matcher 확장이 아니라 관리자 경로의 실패 응답 분기**입니다 — 페이지는 로그인으로 리다이렉트, API 는 401 JSON. 분기 설계는 §5.

> ✅ **2026-08-10 해소.** `isAdminPath()` 가 `/admin` 페이지와 `/api/admin` 을 함께 판정하고,
> 실패 응답을 리다이렉트 / 401 JSON 으로 가릅니다. `(console)/layout.tsx` 2차 가드도 함께 들어갔습니다.

### 디자인 토큰 — 3개만 추가

`globals.css @theme` 의 13개 토큰이 이미 핸드오프와 **값까지 일치**합니다. 추가는 셋뿐입니다.

```
--color-mint-200: #C7DED1   /* 차트 보조 계열 */
--color-track:    #EEF3EF   /* 진행바 트랙 */
--color-danger:   #C0492E   /* KPI 델타 경고 */
```

> 소진 경고와 잔여 임계 색을 제외하면서 `danger-bg`·`danger-line`·`danger-text` 가 불필요해졌습니다. `danger` 는 KPI 델타 표시(증가 `green-600` / 경고 `danger`)에만 남습니다.

### 사이드바 메뉴 — 4개

핸드오프의 `SYSTEM` 섹션(감사 로그·관리자 계정)은 둘 다 기각이라 **섹션째 사라집니다.** `OPERATION` 하나에 대시보드 / 발급 이력 / 경품 현황 / 당첨 내역 4개입니다.

### 2-1. `/admin/prizes` → "경품 현황"

핸드오프의 경품 관리 화면은 **우리 프로젝트에서 동작할 수 없습니다.** 사전 배정 모델이라 확률은 이미 발급된 100장의 코드에 확정되어 박혀 있어, 가중치를 편집해도 바뀌는 것이 없습니다.

조회 전용 전환으로 이 문제가 저절로 풀렸습니다. **편집 대상을 다른 것으로 바꾸는 대신, 편집을 아예 없앴습니다.** 핸드오프 2층 문법("파생값은 편집 불가")을 끝까지 밀면 이 화면은 전부 읽기 전용이 됩니다.

| 핸드오프 컬럼 | 우리 컬럼 | 성격 |
|---|---|---|
| 가중치 (입력) | — (분배 계획은 `db:issue --plan` 으로) | **삭제** |
| 확률 = `weight ÷ SUM` | 발급 비율 파생 — `formatOdds()` 를 공개 서비스에서 이관 | 읽기 전용 · **관리자 전용 정보** |
| 잔여 = `stockLeft` | `count(status='UNUSED')` 집계 | 읽기 전용 |
| 노출 토글 | — (백엔드 `deletedAt`) | **삭제** |
| 푸터 "가중치 합계 160 · 전원 당첨" | "발급 합계 N · 전원 당첨 (미당첨 없음)" | 표시만 |

### 2-2. 폴더 취급

- `admin_handoff/` 는 **읽기 전용 원본**입니다. 수정하지 않습니다. 기각 결정은 이 문서에 적습니다.

#### 착수 후 바뀐 판단

**1) Route Group 은 `(app)` 하나만 만들었습니다.** 관리자 화면이 전부 `/admin` 아래라
`(admin)/admin/…` 은 한 겹이 헛돕니다 — `(admin)/layout.tsx` 와 `admin/layout.tsx` 가
하는 일이 정확히 같습니다. 견적이 말한 분리의 핵심(루트에서 `AppShell` 을 걷어내기)은
`(app)/layout.tsx` 로 이미 끝났습니다. 대신 `admin/` **안에** `(console)` 그룹을 뒀습니다 —
로그인 화면을 인증 가드 밖에 두는 데 실제로 필요합니다.

**2) `?next=` 에 쿼리를 싣지 않습니다.** §5 가 경고한 RSC 문제의 실제 형태는
"302 를 따라간다" 가 아니라 **`_rsc=…` 내부 파라미터가 `next` 에 섞여 들어오는 것**이었습니다.
`pathname` 만 실으면 RSC 헤더를 따로 볼 필요 없이 사라집니다. 콘솔은 필터를 URL 에
담지 않으므로 잃는 것이 없습니다. (소프트 내비게이션이 전체 리로드로 떨어지는 것은 남습니다.
목적지가 로그인 화면이라 어차피 전체 리로드가 맞습니다.)

**3) 사이드바 카운트는 `DashboardResponse` 를 쓰지 않습니다.** 대시보드를 통째로 부르면
재고 집계와 최근 당첨 조회까지 딸려오는데, 뱃지에 필요한 건 두 숫자뿐입니다.
`getNavCounts()` 로 분리해 `count` 2방으로 끝냅니다. — 콘솔 레이아웃은 **페이지를 옮길 때마다**
도는 코드라 여기가 무거우면 화면 전환 전체가 느려집니다.

평문을 넣으면 컴파일이 막게 했습니다. `decryptPhone` 은 이제 **마스킹 직전에만** 불립니다.

## 5. `proxy.ts` 경로 분기 — 채택 (분기 + 2차 가드)

> 📌 **현재 상태**: 사이트 게이트 작업으로 matcher 는 이미 전 경로를 덮고 있고, `isApiPath()` 헬퍼와 `unauthorizedJson()` 도 있습니다. 아래에서 **새로 할 일은 관리자 실패 응답을 페이지/API 로 가르는 것**뿐입니다.

관리자 인증에 실패했을 때, 지금은 경로와 무관하게 401 JSON 을 돌려줍니다. 페이지에는 로그인 화면으로 보내야 합니다.

```ts
// proxy() 의 관리자 분기 catch 안
return isApiPath(pathname)
  ? unauthorizedJson("관리자 인증이 필요합니다.")
  : NextResponse.redirect(loginUrl);
```

### 유리한 점

1. **인증 판정이 한 곳에 남습니다.** 가드를 레이아웃·페이지로 내리면 새 화면을 추가할 때마다 기억해야 하고, 빠뜨려도 화면은 멀쩡해 보입니다(데이터만 비어 있음). matcher 는 경로 패턴이라 새 페이지가 자동으로 보호됩니다.
2. **렌더 이전에 차단됩니다.** 레이아웃 가드는 서버 컴포넌트 트리가 만들어지기 시작한 뒤에 돕니다. proxy 는 그 앞이라 DB 조회가 아예 일어나지 않습니다.
3. **응답 형식이 소비자와 맞습니다.** `fetch` 는 `api-client` 가 아는 `ApiFailure` 를, 브라우저 내비게이션은 로그인 화면을 받습니다.
4. **토큰 만료 UX.** TTL 8시간이라 현장 운영 중 반드시 한 번은 만료됩니다. 리다이렉트면 스스로 복구됩니다.
5. **`SameSite=Strict` 부작용 흡수.** 메신저·메일에서 `/admin` 링크로 들어온 최초 내비게이션에는 쿠키가 붙지 않습니다. 리다이렉트면 자가 치유되고, 401 JSON 이면 깨진 화면입니다.

### 불리한 점과 대응

| 위험 | 대응 |
|---|---|
| Next 라우터가 `/admin/...` 로 보내는 **RSC 페이로드 요청**(`RSC: 1` 헤더)을 경로만 보고 "페이지"로 판정 → 302 를 따라가며 소프트 내비게이션이 전체 리로드로 떨어짐 | 경로 + `RSC` 헤더를 함께 판정 |
| 로그인 페이지를 예외에서 빠뜨리면 **무한 리다이렉트** | `PUBLIC_ADMIN_PATHS` 에 `/admin/login` 을 함께 넣어 **한 배열로** 관리 |
| `?next=` 로 **open redirect** | `/admin` 으로 시작하는 상대 경로만 허용 |
| ~~matcher 가 `_next`·정적 자원까지 잡으면 CSS·JS 가 리다이렉트됨~~ | ✅ 게이트 작업에서 제외 패턴을 이미 적용. **확장자 목록은 `public/` 에 새 형식을 추가할 때만 손대면 됩니다** |
| **proxy 가 단일 실패점**. matcher 오타 하나로 전체 무방비가 되는데 화면은 정상 동작해 **눈에 보이지 않음** | **`(admin)/layout.tsx` 2차 가드** |

2차 가드는 `cookies()` 를 읽어 `verifyAdminToken` 을 한 번 더 돌리는 10줄짜리입니다(0.25h). 사이드바 계정 카드를 그리려면 어차피 토큰을 읽어야 합니다.

`AdminUserDto` 를 쓰는 곳은 `src/app/api/admin/user/route.ts` 하나뿐이고 **UI 는 아직 없습니다.** `decryptPhone` 호출부도 위 2곳이 전부입니다. 실제 파급은 파일 2개 — **지금이 가장 싼 시점**입니다.

### B안 — 마스킹 + 조회 기반 대조

목록은 마스킹만 보여주고, 본인 확인은 **운영자가 고객에게 이름·번호를 물어 입력**하면 서버가 해시로 대조합니다. `GET /api/admin/user?phone=` 가 이미 이 모양이라 응답에서 평문만 빼면 됩니다.

- `AdminUserDto.phone: string` → `phoneMasked: string` 으로 **필드명을 바꿉니다.** 평문을 실수로 넣으면 컴파일이 막습니다.
- **평문이 서버 밖으로 나가는 경로가 0개**가 됩니다. 복호화는 대조에만 쓰이고 응답에 실리지 않습니다.
- 현재 관리자 지급 경로는 `findByPhoneOrThrow(db, phone)` 로 **이름 대조를 생략**합니다. 이름을 화면에 보여주지 않기로 한 이상, 이름을 입력받아 대조해야 확인 수단이 성립합니다 → 5.5 의 "이름 복합 대조" 0.25h.

마스킹 규칙 (`src/lib/mask.ts` 신규, 서버 전용):

| 입력 | 출력 | 규칙 |
|---|---|---|
| `김은서` | `김O서` | 첫·끝 남기고 가운데 전부 `O` |
| `김철` | `김O` | 2글자는 끝 글자를 가림 |
| `남궁민수` | `남OO수` | 4글자 이상도 같은 규칙 |
| `01048214821` | `010-****-4821` | 앞 3 + 뒤 4 |

적용 대상: `AdminUserDto.phoneMasked`·`.name`, `recentReceived.userName`, 당첨 내역 목록.

> 지급 화면은 "성함을 보고 맞추기"가 아니라 **"입력해서 맞추기"** 가 됩니다. 현장 운영 방식이 전자에 익숙하다면 5.5 착수 전에 되돌리세요(지급 화면만 평문, 목록은 마스킹).

## 7. 터질 수 있는 문제

### 7-1. 상품을 지우면 관리자 재고 표에 보이지 않는 재고가 생깁니다 ⚠️

`Product.visible` 을 폐기하면서 초안의 `listActive` 3개 호출부 문제는 사라졌지만, **`deletedAt` 에 같은 구조의 문제가 실재합니다.** 상품 삭제를 백엔드에서 직접 하기로 했으므로 이제 실제로 밟게 됩니다.

목록과 집계의 모집단이 다릅니다.

- 목록 — `productRepository.listActive(db)` : `deletedAt` 이 없는 상품만
- 집계 — `rewardRepository.groupByProductStatus(db)` : **전체 코드** (삭제된 상품 것도 포함)

`adminService.getStock()` (`admin.service.ts:82`) 이 이 둘을 맞물려 씁니다. 코드가 이미 발급된 상품을 soft delete 하면 **그 상품의 미사용 코드가 재고 집계에서 통째로 사라집니다.** 한눈에 확인하는 것이 존재 이유인 콘솔에 보이지 않는 재고가 생기는 셈입니다.

> 📌 **같은 원인의 공개 화면 쪽 문제는 해소 예정입니다.** `prize.service.ts:28-40` 도 같은 구조라 상품을 지우면 공개 확률 합계가 100% 미만으로 떨어졌는데(에코백 40% 를 지우면 나머지가 60% 로 표시), [Phase 4 후속 — 사용자 화면 확률 표기 제거](./implementation-plan.md#phase-4-후속--사용자-화면-확률-표기-제거-2026-08-09)로 확률 표기 자체가 사라지면서 함께 없어집니다.
>
> **다만 관리자 재고 표 문제는 그대로 남습니다.** 확률 제거로 해결되지 않습니다.

### 대응: 발급된 코드가 있는 상품은 삭제를 막습니다 (확정)

`deletedAt` 을 **"발급 전 상품 정리"에만 쓰는 규칙**으로 좁힙니다. 사전 배정 모델에서는 발급된 코드가 곧 계약이라, 그 상품을 목록에서 지우는 것 자체가 집계 오류를 만듭니다.

- 규칙을 `docs/implementation-plan.md` 확정 결정 표에 기록 (완료)
- `productRepository.softDelete()` 에 가드 추가 — 해당 상품의 `reward_codes` 가 1건이라도 있으면 거부. 상품 삭제를 CLI·직접 조작으로 하기로 했으므로 **가드는 레포지토리 레벨**에 있어야 합니다
- 견적 영향 없음 (규칙 문서화 + 가드 몇 줄)

> 검토했으나 채택하지 않은 대안 — **집계 모집단도 활성 상품으로 제한.** 합계는 맞지만 유통 중인 코드를 집계에서 빼므로, 관리자가 보는 재고가 실제보다 적어집니다. 없는 재고를 만드는 대신 있는 재고를 숨기는 것이라 더 나쁩니다.

### 7-2. Route Group 분리

- **`Providers`(TanStack Query)는 루트에 남겨야 합니다.** `AppShell` 만 `(app)` 으로 내립니다. 둘을 같이 옮기면 지급 화면의 mutation 이 깨집니다.

### 7-3. 그 밖

- **서버 컴포넌트에서 `adminService` 직접 호출 시 Prisma 타입 유입.** Phase 2 에서 겪은 문제입니다. 테이블이 정렬·필터 때문에 클라이언트 컴포넌트가 될 가능성이 높으므로 **DTO 변환 후 props 로** 내립니다.

- **`test:api`(47건)가 `receive` 경로 이관으로 깨집니다.** 5.5 검증에 포함되어 있습니다.
- **⚠️ `src/lib/design/codeSchema.ts` 는 죽은 파일입니다 — 여기를 고치지 마세요.** 어디서도 import 되지 않습니다(2026-08-09 확인). 그런데 `CODE_PATTERN`·`normalizeCode` 를 재export 하고 `codeField` 와 거의 같은 스키마를 따로 정의하고 있어서, 코드 검증을 손볼 때 **검색 결과에 먼저 걸리기 쉽습니다.** 여기를 고치면 아무 효과가 없고 원인을 찾느라 시간을 씁니다. 살아 있는 쪽은 `src/lib/reward-code.ts` (`CODE_PATTERN`·`normalizeCode`) 와 `src/lib/validation.ts` (`codeField`) 입니다. 프로토타입 잔재로 보이지만 **지금은 지우지 않기로 했습니다.**
- **조회 전용이라 화면에서 고칠 수 있는 게 없습니다.** 현장에서 이상을 발견하면 터미널을 열어야 합니다. `db:seed`·`db:issue`·`db:stock`·`db:verify` 를 실행할 환경(`.env` 포함)이 현장 노트북에 준비되어 있어야 합니다.

## 8. 1280px 기준 — 채택

### 조사 결과: 레이아웃은 이미 대부분 유동적

`Admin Canvas.dc.html` 의 고정 폭은 사실상 셋뿐입니다.

| 값 | 용도 | 1280 대응 |
|---|---|---|
| `width:1440px` ×2 | 콘솔 셸 | 유동으로 전환 |
| `width:224px` | 사이드바 | **그대로 유지** |
| `width:709px` ×2 | 차트 패널 | 목업이 `1.55fr` 의 계산 결과를 박아둔 값. 실제 구현은 `fr` 을 쓰므로 **작업 없음** |

그리드는 전부 분수입니다 — `repeat(3,1fr)`, `1.55fr 1fr`, `1fr 1fr`.

### 1280px 실측

콘텐츠 폭 = `1280 − 224(사이드바) − 56(좌우 패딩)` = **1000px** (1440 기준 1160px 대비 −14%)

| 요소 | 1440 | 1280 | 판정 |
|---|---|---|---|
| KPI 카드 3장 | 377px | 324px | 여유 |
| 차트 패널 | 697px | 599px | 막대 14개가 38.5px → **31.6px**. 읽기 무리 없음 |
| 잔여 게이지 패널 | 449px | 387px | 여유 |
| 최근 당첨 테이블 7컬럼 | — | **약 974px 필요** | **여유 26px — 병목** |

테이블이 유일한 제약입니다. 시각·코드·연락처가 monospace 고정폭이고 패딩이 `22/12px` 라 가변 폭 컬럼은 경품명뿐입니다. **경품명에 `truncate` 를 걸면 들어갑니다** (`스타벅스 기프트카드 5만원` 이 15자로 최장).

### 시간: 5.1 에서 함께 결정하므로 +0.5h

셸을 `min-width:1120px` + 가로 스크롤로 잡고 1440 을 애초에 하드코딩하지 않습니다. 5.4 까지 만든 뒤 소급하면 2.0h — **리팩터링 비용이 아니라 결정 비용**입니다.
